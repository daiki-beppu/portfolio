# 自己PR

## 一言で

異業種から完全独学でエンジニアに転職し、約1年半で BtoB 業務アプリの FE を一人で設計・構築できるようになったフロントエンドエンジニアです。「失敗から学び、次のプロジェクトで設計を進化させる」サイクルを回し続けています。

---

## 1. 失敗を設計に変える力

エンジニア歴が短い分、失敗も多く経験しています。ただ、同じ失敗は繰り返しません。

| 失敗 | 学び | 次のプロジェクトでの改善 |
| --- | --- | --- |
| Props が肥大化して拡張困難に | 「何を表示するか」は利用側に委ねる | コンポジションパターンを標準採用 |
| 共通化を省略 → 仕様変更で全箇所修正 | 共通化は「変更に強くする」ためにやる | 仕様変更を前提にした設計を徹底 |
| 一覧画面で N+1 フェッチ | データ取得戦略はコンポーネント設計の段階で決める | バッチ取得・プリフェッチを前提に設計 |
| Context ベースのモーダルで SC の利点を消失 | フレームワークの進化に合わせて設計を更新する | queryParams による状態管理に切り替え |

3つのプロジェクトを並行して担当する中で、前のプロジェクトの失敗を次のプロジェクトの設計に即座に反映してきました。経験年数の短さを、改善サイクルの速さで補っています。

---

## 2. 一人で FE を立ち上げる実行力

3つのプロジェクトすべてで、FE の設計・実装をほぼ一人で担当しています。

- **ゼロベースの FE 基盤構築**: ディレクトリ設計、共通コンポーネント、CI/CD、Linter/Formatter、認証・認可、テスト基盤を一人で構築
- **大規模フォーム**: 52フィールド、タブ間の双方向状態同期、複雑なバリデーションを設計・実装
- **大規模マイグレーション**: Next.js 14→15 / React 18→19 / Chakra UI v2→v3 の同時アップグレードを AI を活用して約1ヶ月で実施（現在検収中）
- **100件超のフィードバック**: 品質が不安定だった2アプリのフィードバック対応を2ヶ月で安定化

「設計から実装、基盤整備まで一人で回せる」ことは、少人数チームにおいて大きな価値だと考えています。

---

## 3. チームの生産性を底上げする DX 改善

自分の作業効率だけでなく、チーム全体の開発体験を改善することに注力しています。

**Linter / Formatter の進化**
- ESLint flat config 対応 → Biome → ultracite と、プロジェクトごとに最適なツールを選定・導入

**CI/CD・品質基盤**
- GitHub Actions による PR チェック（build / lint / test）
- lefthook による pre-commit 整備
- TDD 運用の確立（AI 駆動開発との親和性を活かし、仕様駆動で品質を担保）

**コードレビュー文化の推進**
- PR テンプレートの整備と運用定着
- レビュー文化がなかったチームにレビュープロセスを導入

**AI ツールの社内導入**
- Claude Code のサブスクリプション開始後、個人で検証した上でチーム導入を提案（2025年6月）
- 社内用のカスタムスキルを整備し、チーム全体の AI 活用を推進

---

## 4. 業務外での技術への取り組み

業務時間外でも、技術的な探求と実装を継続しています。

### YouTube チャンネル自動運用システム（Python）

AI API（SunoAI / Gemini / Veo）と YouTube API を組み合わせ、企画→楽曲生成→動画制作→投稿→分析の全工程を自動化するシステムを構築。現在2チャンネル（1チャンネル稼働中、1チャンネル準備中）。

- 8ステップの自動化パイプラインを設計・実装
- Claude Code のカスタムスキル21個で全ワークフローを操作
- テンプレートリポジトリを整備し、新チャンネルの横展開を容易に

### specv — Markdown プレビュー CLI（TypeScript）

ローカルの Markdown を GitHub スタイルで表示する CLI ツールを開発し、npm に公開（v0.2.0）。React 19 + Hono + Vite で構築。Playwright E2E テスト、npm Trusted Publishing による自動配布まで整備。

### dotfiles — Nix ベース環境管理

macOS の開発環境全体を nix-darwin + Home Manager で宣言的に管理。CLI ツール、GUI アプリ、macOS 設定、Claude Code のスキル・設定まで、すべてを Git 管理下に置いている。

## まとめ

- **経験年数は短いが、改善サイクルが速い** — 失敗→学び→次のプロジェクトへの反映を高速で回す
- **一人で FE を立ち上げられる** — 設計、実装、基盤整備、品質管理まで一人で完結できる
- **チームの生産性に貢献する** — DX 改善、レビュー文化、AI ツール導入で周囲の生産性も向上させる
- **業務外でも手を動かし続けている** — AI × 自動化の個人プロジェクトで技術の幅を広げている
