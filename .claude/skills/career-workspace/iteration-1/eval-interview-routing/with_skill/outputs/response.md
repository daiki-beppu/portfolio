# SmartHR 面接準備ガイド

来週の SmartHR の面接に向けて、プロファイルと企業分析をもとに準備すべきことを整理しました。

---

## 1. 必ず語れるようにしておくべきストーリー

### 志望動機（なぜ SmartHR か）

核心は **「開発組織のバリューとの共鳴」** です。以下の3つのバリューと自分の経験を紐づけて語れるようにしておきましょう。

- **光（まずやってみる）**: 鳶職からエンジニアへの転職自体が「まずやってみた」結果。技術選定でも未経験の技術を個人検証してからチームに導入してきた（Claude Code、Biome、shadcn/ui など）
- **象（フィードバック文化）**: 現職で最も不足しているのがシニアからのフィードバック。自分で PR テンプレートやレビュー文化を推進してきたからこそ、それが文化として根付いている環境で成長したい
- **偉業（期待を超える）**: 受託開発でありながらモノレポ化の提案、AI ツールの社内導入など、言われていないことを自発的に提案してきた

**注意点**: 人事労務ドメインへの熱量が薄いことは自覚済み。「技術環境とチーム文化が合えばドメインへの情熱は後からついてくる」という考えを正直に伝えつつ、「一つのプロダクトを長期的に育てたい」という転職理由と結びつけるのが自然です。

### 転職理由

ネガティブに聞こえないように注意。ポイントは：

- 現職への感謝を明確に述べる（未経験で FE を任せてくれた、技術選定の自由度が高かった）
- その上で「次に必要なもの」として、シニアからのフィードバック・高い技術基準・自社プロダクトへの関与を挙げる
- 「不満ではなく成長のための選択」というトーンで統一する

### 自己 PR の軸

1. **失敗を設計に変える力**: 3プロジェクト並行の中で、前のプロジェクトの失敗を次に即座に反映。PJ3 では過去全ての学びを活かしたゼロベース設計を実現
2. **FE 領域を自走する実行力**: 少人数チームで FE の設計・実装・基盤整備を一貫して担当
3. **チーム全体の生産性を底上げする DX 改善**: AI ツール導入、Linter/Formatter 整備、CI/CD 構築

## 2. 技術面接で聞かれそうなこと＆準備

### 設計判断について

以下のエピソードを具体的に説明できるようにしておく：

- **コンポジションパターンの採用理由**: Props 肥大化の失敗 → 「何を表示するか」を利用側に委ねる設計に転換した経緯
- **モノレポ化の提案と実行**: 課題の言語化（UI 不統一、バージョン差異）→ 解決策の提案 → AI を活用した1ヶ月での完了
- **queryParams によるモーダル管理**: Context ベースで Server Component の利点を消失した反省 → nuqs での型安全な状態管理
- **N+1 フェッチの改善**: データ取得戦略をコンポーネント設計段階で決める方針への転換

### 技術的に深掘りされそうなポイント

- React Server Components / Server Actions の使い分け
- 大規模フォーム（52フィールド、タブ間の双方向状態同期）の設計
- Next.js 14→15 / React 18→19 / Chakra UI v2→v3 の同時アップグレードで苦労した点と解決策
- TDD と AI 駆動開発の組み合わせ方

### 正直に伝えるべき課題

- CS の基礎（アルゴリズム、データ構造、ネットワーク）が体系的でない → 独学で補完中
- 大規模チームでの開発経験がない → だからこそ SmartHR で経験したい
- 設計パターンの引き出しがまだ少ない → シニアからのフィードバックを求めている

## 3. 逆質問の準備

企業分析の「要確認事項」をベースに、以下を用意しておきましょう。

### 技術・チームに関する質問

1. **FE チームの構成と規模は？ シニアエンジニアはどのくらいいるか？** → 転職理由の核心に直結するので最重要
2. **具体的な技術スタックは？（React / Next.js / デザインシステムなど）** → 求人票に詳細がなかったため確認
3. **コードレビューのプロセスは？ どのような観点でレビューしているか？** → 「象」バリューの実態を確認
4. **AI 駆動開発への取り組み状況は？** → 自分の強みを活かせるか確認

### キャリアに関する質問

5. **オープンポジションからリーダーへのキャリアパスはどうなっているか？**
6. **入社後のオンボーディングはどのような流れか？**
7. **新しいツールや技術の導入提案はどのようなプロセスで行われるか？** → 自発的な改善提案が歓迎されるか確認

## 5. 面接で気をつけるポイント

### 経験年数の短さへの対処

「1年半」という数字だけ見ると短いが、以下で補う：

- 3プロジェクト並行という密度の高さ
- 改善サイクルの速さ（失敗→学び→次のプロジェクトへの即時反映）
- 業務外での継続的な技術活動（YouTube 自動化、specv、dotfiles）
- 実質テックリードとしての意思決定経験

### バリュー NG 例への自覚

SmartHR のバリュー NG 例に自分が当てはまる部分がある（こだわりすぎる、やりたいことに寄る傾向）ことを自覚しており、「まずはこだわりを捨ててみる」ことを意識していると正直に伝えられると、自己認識の深さを示せます。

### 鳶職の経験の活かし方

「段取り力」と「粘り強さ」を具体的なエピソードと紐づける：

- 段取り力 → プロジェクトの設計判断、API 仕様の事前すり合わせ
- 粘り強さ → 100件超のフィードバック対応を地道にやり切った
