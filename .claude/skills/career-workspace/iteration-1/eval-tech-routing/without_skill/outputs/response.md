# FE 特化 vs フルスタック：現状分析と提案

## 現状の整理

ポートフォリオから読み取れるプロフィール:

- **経歴**: 鳶職 → 独学 → 受託開発スタートアップ（2024.10〜）
- **実務経験**: 約1年半、BtoB 業務アプリの FE が中心
- **メインスキル**: TypeScript / React / Next.js / TanStack Query / Tailwind CSS
- **サブスキル**: Python, Shell Script, SQL
- **特徴**: FE 基盤をゼロから一人で設計・構築できるレベル。DX 改善や AI ツール展開などチーム貢献にも強み

## 結論から言うと

**今は FE 特化を軸にしつつ、必要に応じてバックエンド領域を「つまみ食い」するのが最も合理的。**

理由を以下に述べる。

## FE 特化を推す理由

### 1. 今の武器が一番伸びるタイミング

実務1年半で FE 基盤を一人で設計・構築できるのはかなり速い成長ペース。ただ「設計できる」と「設計の引き出しが豊富」は別物で、ここからあと1〜2年 FE に集中すると以下が身につく:

- 大規模状態管理の設計パターン（複数アプリ間の共通化、キャッシュ戦略）
- パフォーマンス最適化の実践知（Core Web Vitals、バンドル最適化、レンダリング戦略）
- アクセシビリティ / デザインシステム構築
- モノレポ・CI/CD パイプラインの設計

これらは「FE を極めた人」と「FE もできるフルスタック」を明確に分ける差別化ポイントになる。

### 2. 市場価値の観点

日本の転職市場では「FE 特化で設計・基盤構築ができる人」の需給ギャップが大きい。フルスタックは人数が多いが、FE アーキテクトレベルの人材は圧倒的に少ない。年収レンジも FE 特化のシニア〜リードで 700〜1000 万円帯が狙える。

### 3. 独学エンジニアとしてのストーリー

「鳶職から独学で FE を極めた」というキャリアストーリーは非常に強い。ここにフルスタックを混ぜると「広く浅い人」に見えるリスクがある。まずは一本の柱を太くする方が説得力が出る。

## ただし「完全に FE だけ」は危険

### つまみ食いすべき領域

今のスキルセットを見ると、Hono（specv で使用）や Cloudflare Workers を既に触っている。この延長線で以下は自然に拾える:

- **API 設計（REST / tRPC）**: FE から見た「良い API」を語れると FE としての価値も上がる
- **DB の基本（SQL は既にある）**: テーブル設計の基礎があれば BE とのコミュニケーションが格段に良くなる
- **インフラの基礎（Cloudflare / Vercel）**: 既にやっている。Edge Computing の知識は FE エンジニアとして差別化になる

これらは「フルスタックになる」ではなく「FE の守備範囲を広げる」という位置づけ。

## 具体的な 12 ヶ月ロードマップ案

| 期間        | やること                                                                        | 狙い                                         |
| ----------- | ------------------------------------------------------------------------------- | -------------------------------------------- |
| 1〜3 ヶ月   | 実務で FE 設計の引き出しを増やす。React Server Components / App Router の深掘り | FE の「深さ」を出す                          |
| 4〜6 ヶ月   | テスト戦略の確立（Vitest + Playwright の実践パターン蓄積）、CI/CD 改善          | 品質担保できる FE エンジニアとしてのブランド |
| 7〜9 ヶ月   | パフォーマンス最適化、アクセシビリティの実践                                    | シニア FE に必要な教養                       |
| 10〜12 ヶ月 | tRPC or GraphQL + DB 連携の個人プロジェクト                                     | BE 領域の「つまみ食い」で守備範囲拡張        |

## 判断基準：フルスタックに舵を切るべきタイミング

以下のどれかに当てはまったら、フルスタック方向に本格シフトを検討して良い:

1. **FE の設計・実装で「もう新しい学びがほとんどない」と感じたとき**（目安: FE 実務 3〜4 年）
2. **自分のプロダクトを作りたくなったとき**（個人開発で BE が必要になる）
3. **マネジメントではなく技術で食っていきたいと確信したとき**（T 字型のスキルが必要）

## まとめ

- 今の成長曲線を考えると、FE 特化であと 1〜2 年は突き抜ける方が ROI が高い
- 「FE 特化」は「FE しかやらない」ではなく、FE を軸にしつつ隣接領域（API 設計、Edge、DB 基礎）を自然に広げるイメージ
- フルスタックは「FE で十分な自信がついてから」でも遅くない。逆に今フルスタックに行くと、どちらも中途半端になるリスクがある
