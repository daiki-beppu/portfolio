# 転職理由

## 前提

現職に対する不満から転職を考えているわけではない。未経験の自分に FE を一人で任せてくれたこと、技術選定やツール導入の提案を自由にさせてくれたこと、短期間で3つのプロジェクトを並行して経験できたことには感謝している。

## なぜ転職を考えているか

現職で得られた「幅広い経験」と「自由度」に感謝しつつも、次のステップとして以下を求めている:

### 1. 高い技術基準を体で覚える

コード品質や設計に対する高い基準が当たり前の組織に身を置きたい。現職では DX 改善やレビュー文化を自分が推進してきたが、「引き上げる力」は証明できても「何を基準として引き上げるか」の解像度は自分の経験範囲に制約される。高い基準を持つ組織で、コードレビュー・設計レビュー・テスト戦略などの基準を肌感覚として身につけたい。

学びの機会は組織の中だけにあるとは考えていない。コミュニティへの参加、登壇での質問、OSS への関与など、自分から取りに行ける環境は自分で整備できる。ただし、日常の業務を通じて高い基準に触れ続ける経験は、組織に入らないと得られない。

経験1.5年〜2年の今がポテンシャル採用で突破できるタイミングであり、経験3年を超えると即戦力として求められる水準が上がる。「高い基準を知った上で、次の環境で引き上げる側に回る」というキャリアパスを意識している。

### 2. 情熱を持てるプロダクトへの関与

受託案件を並行して進める中で、一つのプロダクトを長期的に育てたいという気持ちが強くなった。自分が愛着を持てるプロダクトに対して、技術的な意思決定がプロダクトに反映される実感を持ちながら働きたい。

### 3. 総合的な評価

報酬、技術的な機会、役割・ポジションを含め、自分の成果と成長に見合った評価をしてくれる環境で貢献したい。

## まとめ

現職への感謝を持ちつつ、「高い技術基準を体で覚え、次のステージでそれを広げる側に回る」というのが転職の動機。学びは自分で取りに行けるが、日常の業務で高い基準に浸かる経験は今このタイミングで得ておきたい。

## 面接で使う確定版（v2, 2026-04-23 セッションで結晶化）

※ 上記は思考の整理。下記が面接・書類・スカウト返信で実際に使う結晶化バージョン。

### 🟦 Push（なぜ現職を離れるか）

> 現職では受託開発で FE を一人で任せていただき、技術選定・開発環境の整備を自分の裁量で進めてきました。未経験から短期間で 3 つのプロジェクトを並行して経験し、その中で ESLint から Biome、ultracite への Linter 移行、knip による不要コード検出、PR テンプレートの整備など、**コード品質を仕組みで担保する取り組み**を積み重ねてきました。
>
> 加えて、**キャッチアップした技術やプラクティスは社内で継続的に発信している**のですが、**議論やフィードバックが返ってくることはほとんどなく**、自分の理解が正しいか、チームで導入する価値があるかを問い直せる相手が組織内にいない状態が続いています。
>
> 技術選定も品質の仕組みも自分一人で判断してきた分、**判断の基準は自分の経験範囲の中に閉じている**という実感があり、「自分の中で正しい」が本当に正しいかの検証機会が構造的に不足しています。レビュー文化やテスト戦略など、**基準の高い人たちと日常的に仕事をする環境で、自分の判断の物差しを育てていきたい**と考えています。

**ポイント**:

- 「引き上げる側」「高基準に浸かる」などの自分に酔った表現は排除
- 事実ベース（「自分の裁量で進めてきた」「一人で判断してきた」「社内で継続的に発信している」）
- 「反応がない」は愚痴ではなく **「検証機会の構造的不足」** として語る（組織批判ではなく構造認識）
- 吸収する主体は自分（「自分の判断の物差しを育てる」）

### 🟥 Now（なぜ今か）

> 経験 1 年半のいま、「**学びに行く動機**」で転職活動をするのが自然なタイミングだと考えています。経験が進むほど採用側の期待値は「即戦力」に寄っていくので、「**基準を学びに行く**」という動機を素直に言える期間は長くないと感じています。
>
> もう一つ、学びの機会は組織の中だけにあるとは考えていません。個人開発（specv、Claude Code のカスタムスキル整備、dotfiles）、OSS 公開、発信など、自分から取りに行く活動は続けてきました。その上で、**日々の業務の中で基準の高い人と向き合う経験だけは、組織に入らないと得られない**。この 2 つが重なる今、環境を変えたいと考えています。

**ポイント**:

- 「最後のウィンドウ」「3 年の壁」などの強い語は排除
- 「動機を素直に言える期間は長くない」のマイルドな表現
- 能動性（自分から取りに行く活動を続けている）を明示

### 🟨 Pull（企業ごと差し替えテンプレ）

```
1. プロダクトへの共感（業界文脈の理解）
   → 御社の {プロダクト名} の {具体的な価値提供} に、
     {自分の経験/価値観} の観点から魅力を感じている

2. 技術文化の裏付け
   → {テックブログ/OSS/登壇/技術選定の発信} から、
     {レビュー文化/テスト戦略/アーキテクチャ議論} に対する高い基準を読み取った

3. 自分の軸との接続
   → "AI 時代のコード品質" という私の軸が、
     {御社の AI 活用スタンス / テスト文化 / 品質への投資} と重なる

4. 入社後の貢献イメージ（業界 × 軸のビジネス言語訳）
   → 御社の {事業ドメイン特有の痛み / ビジネス要件} に対して、
     {AI × コード品質 / ハーネスエンジニアリング} を活かし、
     {開発速度の維持 / 本番事故の削減 / 負債返済との両立 など
      ビジネス言語での具体的な価値} を実現したい
```

**運用ルール**:

- **具体の引用が必須**（テックブログのタイトル、登壇スライドの URL、採用ページの技術スタック等を最低 1 つ）
- 「雰囲気が良い」「社員が生き生きしている」は即減点の抽象語
- カジュアル面談で聞き出してから本面接の Pull に仕込む
- **4 は「ビジネスサイド面接官 / 人事 / カジュアル面談序盤」で必ず出す**。技術面接では 3 → 4 の順で出して「軸があってビジネスに接続できる人」を示す
- 4 の文言は **企業ごとに事前準備** する（`company-targets.md` の「入社後の貢献イメージ仮説」または `companies/{company}.md`）
- 4 の粒度は「不動産業界なら VR で内見できるようにします」レベルの **映像化できる具体性**。抽象的な「速くなります」「品質上がります」は NG

### 3 層の一貫性チェック

- Push 単独 = 「逃げ」に聞こえる → Now とセットで「能動的な選択」に
- Pull 単独 = 「リップサービス」に聞こえる → Push/Now とセットで「軸に沿った意図ある選択」に
- 3 つの間に矛盾がないことを必ず確認

### 使い分け

- **カジュアル面談**: Push 軽く + Pull(1 → 4 重点) + Now の順。**4（入社後の貢献イメージ）を必ず入れる**
- **本面接（技術面接官 / CTO / TL）**: Push → Pull(3 → 4) → Now のフルバージョン。L3 技術語り（ハーネスエンジニアリング）を主軸に
- **本面接（ビジネスサイド / 人事）**: Pull(1 → 4) を中心に、Push/Now は軽く。**技術語彙を減らし、ビジネス言語での貢献イメージを主軸に**
- **逆質問**: `company-targets.md` の 6 条件質問を使う
- **スカウト返信**: Pull のみを短く（30 秒版のピッチ + Pull 1 文）
