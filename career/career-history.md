## 失敗と学び

### 1. Props 肥大化 → コンポジションパターン

Button を `label` props で設計 → アイコン追加で拡張困難に。モーダルでも body / footer / bgColor 等の props が肥大化。
**学び**: 「何を表示するか」は利用者に委ねる。コンポジションパターンで拡張性を確保する。

### 2. 共通化の軽視 → 仕様変更で全箇所修正

納期優先でコンポーネントの共通化を省略 → 仕様変更時に全箇所を個別修正する羽目に。
**学び**: 共通化は「きれいにする」ためではなく「変更に強くする」ためにやる。仕様変更は必ず来る前提で設計する。

### 3. N+1 フェッチ

一覧画面で各行ごとに API リクエスト → パフォーマンス悪化。
**学び**: データ取得戦略はコンポーネント設計の段階で決める。バッチ取得・プリフェッチを前提に設計する。

### 4. メモ化の誤用

依存配列の設定ミスで表示が更新されない / 無駄な再レンダリング。
**学び**: React Scan を導入しパフォーマンスを可視化。推測ではなくツールで客観的に判断する。

### 5. Context ベースのモーダル設計

モーダルの開閉を Context + useContext で管理 → Context を consume するコンポーネントが Client Component となり、Server Component の利点（ゼロバンドル・直接データ取得）を活かせない。
**学び**: queryParams で状態管理すれば Server Component のまま扱え、URL で状態共有も可能。フレームワークの進化に合わせて設計パラダイムを更新する。

### 6. 全体的な設計力の不足

経験不足から、抽象化のタイミング判断（早すぎる抽象化 / 遅すぎる抽象化）や全体を見通した設計が甘かった。個々のコンポーネントは書けても、アプリ全体のアーキテクチャを俯瞰した設計ができていなかった。
**学び**: PJ3 でゼロから設計する機会を得て、PJ1・PJ2 の反省をすべて反映。プロジェクトごとに設計力が進化している実感がある。シニアエンジニアからのフィードバックがあればさらに成長できると考えている。
